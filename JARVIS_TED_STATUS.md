## Known Problems

(Consolidated 2026-10-02. Removed as stale or addressed: "old subprocess TTS path"; pause-fragmented utterances (merging passed live); "No audible input" false positive (rule changed, see item 4).)

1. Voice barge-in through laptop speakers is NOT solved live. Full duplex without echo cancellation cuts every reply on echo. With echo cancellation (JARVIS_AEC=1, pywebrtc-audio 0.2.0, tools\aec_live.py) three live runs on 2026-10-02 were mixed: run 1 and run 2 allowed voice interruption (1 and 2 times) but replies were choked or cut at the start by leftover echo; run 3 failed (Jarvis answered its own voice, cancellation 1.7-5.4 dB). Offline on recordings it removed 20-36 dB; live it reached 8-17 dB later in replies; the cause of the gap is unexplained (Account 1 updates 4-8). Operating rule: leave JARVIS_AEC unset; default half-duplex on speakers (no voice interruption), or earphone + JARVIS_FULL_DUPLEX=1.
2. Whisper-server gives bad decodes live that replay cleanly offline: 4 cases in 2 live runs (2026-10-01: seg5 truncated to 10 words, seg6 repetition loop; 2026-10-02: seg6 decoded as "it is" and seg8 as "I mean", 8.48 s and 8.77 s of speech). Replays of the saved WAVs through whisper-server gave full transcripts (2026-10-02: seg6 24 words, seg8 30 words, identical in 3 repeats at the live audio_ctx). Not audio_ctx, not the saved audio. The 2026-10-02 live ASR times were normal, so the earlier slowness link is not general. Account 1 recorded an 18.40 s merged turn decoded completely, so length alone does not explain it. Cause undetermined; the live request code was not compared with the replay request. Transcript guard (retry once when the transcript is far shorter than the speech) not added; whether a live retry would recover is untested. On 2026-10-02 (update 11) four long turns (6.14-9.89 s) decoded in full in one earphone run and the ASR guard was not triggered; before the guard existed, Account 2 saw another repeat-loop decode (its session 2 seg2, "I mean I mean ..."). LLM_MAX_TOKENS = 80: one reply ended with finish_reason=length and was trimmed to its last complete sentence (live, update 11).
3. TurnAssembler: no regression test on the machine (tested only by a scripted harness in Account 1's sandbox). Defaults 800 ms / 250 ms are untested starting values. Burst rejection is not verified on real non-speech noise (only echo bursts seen). Adds about 0.8 s between SPEECH END and TURN READY on every turn.
4. New "digital silence" warning (3 s of exact zeros) not verified on a genuinely blocked or muted mic; only input index 17 (earphone connected) was measured, not index 12.
5. After stop()/abort(), MME can refuse stream.start() (error 33). In one test an immediate restart waited the full 1 s and then reopened the stream; the sentence after the reopen was audible. Whether to shorten the 1 s retry window is open (one run).
6. Single launcher tools\start_jarvis.ps1 (-Mode earphone|speakers, -Aec, -AecDump, -AecMicDelayMs). Earphone mode verified live (cold start and earlier runs); speakers mode ran once with the earphone still connected (not a valid speaker test, update 16); the timeout path and the -Aec switches are not exercised.
7. Input device index is unstable (12 without the earphone recognised, 17 with it). Output is now chosen by name; how stream_asr_test.py chooses its input was not checked by this account.
8. Pipeline shells out to curl.exe for external calls (as recorded 2026-09-06; not re-checked since TTS moved in-process). Ctrl+C mid-request gives "curl failed (exit 3221225786)" = STATUS_CONTROL_C_EXIT, harmless.
9. sd.RawOutputStream (blocking API) is not supported on WDM-KS endpoints (indices 13/14: "Blocking API not supported yet", PaErrorCode -9999). Not a live issue while the named MME device resolves.
10. Occasional ASR misrecognition reported by Tedy, cause not diagnosed (see item 2).
11. Account 2 limits (update 3): "forget everything" clears only the stored facts, not the in-session history or the log; SpeakResult bytes_written and audio_seconds undercount on a mid-chunk cut (stopped_early is reliable); the reply cap LLM_MAX_TOKENS = 80 shortens long answers (Tedy decision, see Next Recommended Step).

## Decisions Made

- Inference engine is self-built llama.cpp (llama-server.exe/llama-cli.exe), not Ollama/LM Studio, independent of the prior Beast Coder stack - M0
- Conversation-history eviction changed from one-pair-per-turn slide to batch reset (RESET_KEEP_TURNS=2 at MAX_HISTORY_TURNS=6) - 2026-09-03
- tts_piper.py calls Piper's Python API directly with a resident output stream, replacing the subprocess approach - 2026-09-06
- TurnState generation-counter approach for turn-cancellation, kept as the mechanism - 2026-09-06
- Hard-coded device=3 in tts_piper.py - 2026-09-07; SUPERSEDED 2026-10-01 by Account 2: device chosen by name ("Speaker (Realtek(R) Audio)", MME) with index 3 as printed fallback
- Output device rule (ACCOUNT3_DEFAULT_OUTPUT_V1 in tts_piper.py): follow the MME default output when it is a Realtek Headphone or Speaker endpoint, else the by-name Speaker lookup, else index 3; resolved once at start-up, so the earphone must be plugged in BEFORE starting - Account 3, 2026-10-02
- Operating rule until AEC exists: earphone + JARVIS_FULL_DUPLEX=1 for voice interruption; speakers + default half-duplex otherwise - Account 1, 2026-10-01
- Operating rule (Account 1, 2026-10-02): leave JARVIS_AEC unset for normal use. The launcher switch -Aec (Account 3 update 15) turns it on for experiments only; the launcher clears every JARVIS_* switch before each run.
- TurnAssembler hold/merge approach with turn-generation bump deferred until speech is confirmed; defaults 800 ms merge gap and 250 ms minimum speech (untested starting values) - Account 1, 2026-10-01
- NEAR_ZERO_PEAK 50 -> 1 (warning = 3 s of exact digital silence) - Account 1, 2026-10-01
- Echo handling direction: AEC with the TTS tap as reference, because echo is louder than the user's speech (see Benchmark Results). AEC dependency decided 2026-10-02: pywebrtc-audio 0.2.0, installed (Tedy wants speaker use without the earphone). Previously: NOT yet decided: the AEC dependency (Tedy's decision).
